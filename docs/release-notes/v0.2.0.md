# ConTicx v0.2.0 — public sandbox booking

The public demo at <https://conticx.vercel.app> takes bookings again: pick a
show, pay with a **Hyperswitch sandbox** test card, get a ticket, find it in My
Tickets, and add it to your calendar. No real money moves; the shows are
fictional. v0.1.x ran the demo browse-only.

## Try it

| Card | Result |
| --- | --- |
| `4242 4242 4242 4242` | succeeds — ticket issued |
| `4000 0000 0000 0002` | declined — nothing charged, seat released |

Any future expiry, any 3-digit CVC. Don't enter a real card.

## Changes

- **Sandbox-only full mode.** Booking routes refuse to run unless the
  provider settings are a Hyperswitch sandbox (sandbox host, `snd_` /
  `pk_snd_` keys).
- **Isolated demo data.** `CONTICX_REDIS_PREFIX` namespaces every Redis key,
  so the demo shares a database with older data without touching it.
- **Declined payments resolve.** Observed in the sandbox: a `failed` payment
  can't be confirmed again unless its profile enables manual retry. The app
  now reads that setting and releases a declined booking's seats only when
  the payment can never be retried; otherwise it keeps them, as before. The
  confirmation page shows "That payment didn't go through" instead of
  waiting forever.
- **Checkout** shows the test cards, waits for the widget to be ready before
  enabling Pay, recovers if the widget's confirm call never returns, and
  re-offers a finished booking only as its outcome.
- **Usage limits.** New guest sessions, new bookings, and status refreshes are
  bounded per client, per guest, and overall (`429` with `Retry-After`);
  retries of an existing booking and provider webhooks are never limited.
- **Operator tooling.** `scripts/demo-ops.ts` reports holds, flagged orders,
  inventory, and usage for the demo namespace, and can re-check flagged
  orders with the provider; see `docs/operations.md`.

## Verification

- Lint, typecheck, the full automated suite, and a production build.
- Against the real sandbox from a local production build: a successful
  booking and ticket, a decline, a reload of the same booking, an expired
  hold cancelled at the provider with its seats returned, a second guest
  refused, and the calendar file.
- The hosted acceptance checks for this release are recorded on its GitHub
  release page.

## Not verified / limitations

- Only the sandbox's dummy card connector; no 3DS, redirect, or wallet flows.
- Refunds, the organizer view, accounts, and cross-device tickets remain
  unavailable.
- Usage limits are coarse fixed windows; clients sharing an address share an
  allowance.

## Upgrade notes

- New, optional: `CONTICX_REDIS_PREFIX`, `CONTICX_RATE_LIMITS`,
  `CONTICX_DEMO_BOOKINGS_PER_HOUR`.
- Full mode now requires sandbox provider settings.
- Local development against the real sandbox: use
  `APP_ORIGIN=http://conticx.localhost:3000` (not `localhost`).
