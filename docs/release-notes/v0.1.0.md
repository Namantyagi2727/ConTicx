# ConTicx v0.1.0 — portfolio release

Public browse-only demo: <https://conticx.vercel.app> — served this release
from 2026-10-25 until it was replaced the same day by
[v0.1.1](v0.1.1.md), which fixes event times showing in UTC.

First tagged release of ConTicx, a concert-ticket booking app built on
Next.js, Upstash Redis, and Hyperswitch. Versioned 0.x deliberately: it is a
portfolio project, not production software.

## Highlights

- **Booking flow:** browse events, ten-minute seat holds, Hyperswitch
  Unified Checkout, QR-code tickets, My Tickets for the current browser.
- **Add to calendar:** confirmed tickets download an RFC 5545 `.ics`
  generated in the browser from the event catalog — the exact start instant
  in UTC, no invented end time, and no order ids or links.
- **Correctness under concurrency:** atomic Redis Lua scripts for
  reservation, status transitions, and payment association; no overselling
  and no double releases under concurrent or retried requests.
- **Authenticated webhooks:** HMAC-SHA512 over the raw body, fail-closed; the
  provider's state is re-read and bound to the order before anything changes.
- **Guest ownership:** HttpOnly session credentials (hash-only storage)
  replace order-id-as-credential; legacy orders stay inaccessible.
- **Idempotent booking attempts:** reloads, retries, lost responses, and
  concurrent submissions resume one order; the provider `payment_id` is fixed
  before any provider call, and payment creation never releases seats.
- **Structured logging and request correlation:** one JSON line per request
  on the booking, order-status, and webhook routes, with server-generated
  request ids and an allow-list that keeps secrets out of logs.
- **Browse-only demo mode:** booking is enabled only with
  `CONTICX_MODE=full`; otherwise every booking, order, ticket, and webhook
  route refuses on the server, and the event page does not touch inventory.

## Verification

- Lint, typecheck, isolated production build, and 239 automated tests
  (45 unit, 194 integration) against local Redis and a fake Hyperswitch.
- Browser checks of the full flow through a local harness with a stub
  payment widget, and of browse-only mode on a production build with no
  environment variables.

## Not verified

- Real Hyperswitch behaviour (webhook delivery, redirects, duplicate
  `payment_id` handling, retrieval) and hosted Upstash parity.
- A booking-enabled deployment. The hosted demo is browse-only; its pages
  and server-side refusals were checked on the live build after
  deployment.

## Known limitations

No background recovery for flagged orders, refunds and the organizer view
disabled, same-browser tickets only, no rate limiting. Event times on the
server-rendered home and event pages use the server's time zone (UTC on the
hosted demo) rather than the venue's. See the README.

## Upgrade notes

- New: `CONTICX_MODE` — set `full` to enable booking; unset means
  browse-only.
- Required in full mode: `APP_ORIGIN`, `HYPERSWITCH_WEBHOOK_SECRET`.
